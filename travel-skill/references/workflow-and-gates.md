## 1. 输入清单

先确认：目标、受众、平台、总时长、画幅、发布规格、叙事主线、地点、季节、情绪、台词、真实素材、参考人物图、模型、单次生成时长、首尾帧能力、授权状态。

缺失信息分两类：

- 会改变故事或制作方法：暂停并询问。
- 可用保守默认值处理：明确假设后继续。

## 2. 素材分工

真实素材优先承担不可伪造的地理、人文、宗教、动物和纪实行为。AI 优先承担固定人物剧情、动作补拍、受控意象和难以实拍的连接镜头。

每项素材记录：文件、类型、地点、画幅、分辨率、文字/水印、来源、授权、人物肖像、文化风险、拟用镜头。

## 3. 生产流程

1. 写一句话核心命题和三段式情绪曲线。
2. 建立真实/AI 素材矩阵。
3. 确定视觉基准：自然光、色彩、镜头克制程度、禁用风格。
4. 为每个候选首帧做空间审计。
5. 写镜头叙事目标与分时段画面内容。
6. 选择一个主运镜并验证物理路径。
7. 设计有动机的光线和曝光策略。
8. 设计尾帧及下一镜衔接。
9. 按模型限制生成提示词。
10. 三轮生成、记录版本与缺陷。
11. 做连续性和风险质检。

## 4. 确认节点

- Gate A：创意方向、故事、总时长。
- Gate B：素材分工、风险提醒、视觉基准。
- Gate C：首帧空间审计、前三镜试生成方案。
- Gate D：完整分镜和生成提示词。
- Gate E：生成结果、修复优先级和剪辑方案。

用户要求只改一镜时，不反向扩展为整片重做。

## 5. 交付与变更

- 镜头 ID 一旦进入生成阶段便保持稳定。
- 删除镜头时标记废弃，不自动让后续镜号前移。
- 记录每次修改影响的时长、首尾帧、台词、音乐点和下游镜头。
- 对尚无首帧的镜头，输出“待补场景图清单”，不要假装已完成。
- `shot-manifest.yaml` 使用 JSON 兼容语法，以便检查脚本只依赖 Python 标准库。
