# Module: Product Introduction

## Objective
Explain a real product's value by showing what it is, how it works, and what outcome it enables. Product truth outranks decorative spectacle.

## Required inputs
- Product name and authoritative source;
- target audience and primary problem;
- verified features and proof;
- product screenshots/recordings/images where available;
- brand assets and claims that must remain exact;
- CTA and delivery context, if any.

## Workflow
1. Separate verified features from aspirational claims.
2. Choose a narrative spine: problem → product → interaction → result → value.
3. Identify which moments require exact UI or text. Prefer real screen recordings or deterministic overlays for these.
4. Define product invariants: shape, color, ports, labels, interface structure, logo, and interaction semantics.
5. Use motion language according to function: UI walkthrough, feature cards, product hero, macro detail, or mechanism build.
6. Pilot the highest-risk product shot before generating all scenes.
7. Review every candidate for product geometry drift, invented UI, impossible interactions, and unsupported claims.

## Product-specific QA
- Does the depicted feature exist?
- Does the action cause the shown result?
- Are UI labels, numbers, buttons, and logos exact?
- Does the product remain the same model across shots?
- Can the viewer understand the benefit without relying on vague narration?
- Are simulated screens clearly treated as illustrative when they are not real product captures?

## Prompt guidance
Describe the actual action and outcome, not just “futuristic interface.” State which reference controls product geometry and which controls lighting/style. Keep one primary interaction per shot. If exact interface fidelity matters, use authentic UI assets and post-production compositing.
