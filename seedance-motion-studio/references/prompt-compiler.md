# Prompt Compiler：从结构化镜头规格到生成指令

## 编译目标

Prompt 应当清晰表达模型需要生成什么、什么必须保留、动作如何发生、镜头如何运动、画面最后停在哪里。它不应复制整份项目背景，也不应混入与当前镜头无关的规则。

## 编译顺序

1. 目标镜头与叙事目的；
2. 主体身份和权威参考；
3. 场景与构图；
4. 动作时间线；
5. 相机运动；
6. 光线、色彩、材质和影像风格；
7. 参考素材职责；
8. 必须保留和允许变化的属性；
9. 声音意图（仅在当前生成入口支持且该镜头需要时）；
10. 结束状态与验收标准。

## 编译检查

- 是否只有一个主要目的？
- 主体、相机和环境的动作是否互相冲突？
- 时间顺序是否明确？
- 是否说明结束状态？
- 参考素材的职责是否明确？
- 必须保留的属性是否与允许变化属性冲突？
- 是否把精确文字、Logo、数据或 UI 错误地交给生成模型？
- 是否要求模型在目标时长内完成过多动作？
- 是否包含不必要的重复形容词或互相矛盾的负面约束？
- 是否针对实际 Seedance 入口的能力编写，而非假设功能存在？

## 负面约束

负面约束应针对明确风险，例如“不要改变产品接口位置”。避免无穷无尽的“不要模糊、不要变形、不要错误、不要低质量”列表。每个负面约束都应能追溯到一个必须避免的失败模式。

## 长度策略

- 简单镜头：短而直接。
- 角色动作镜头：重点写身份锚点、动作顺序和结束状态。
- 多模态镜头：先说明每个参考的职责，再描述运动。
- 高风险镜头：允许更细的结构化约束，但仍需删除重复与矛盾内容。

## 输出形态

优先交付：
1. `Prompt Card`（便于人审与复用）；
2. 面向目标入口的可复制 Prompt；
3. 参考素材清单；
4. 该镜头的验收条件；
5. 生成后需重点检查的风险。

不得把提示词方案描述为已生成结果。
